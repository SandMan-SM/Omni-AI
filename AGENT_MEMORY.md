## 🌐 Patterns To Apply
- **a-request-header-is-not-a-credential** — `x-vercel-cron`, `x-forwarded-*` and `User-Agent` are chosen by the caller, so they are no harder to set than `Authorization`. Two live routes in this repo used one as proof of caller identity: the cron gate accepted `User-Agent: vercel-cron/1.0` on the theory that only Vercel sends it (it does not — every HTTP client does), and the federation-newsletter generator accepted `x-vercel-cron: 1` whenever its secret was unset, which made the bypass the only path in. The general form: **a legacy compatibility shim for a platform's old behaviour becomes an authentication bypass the moment the header is the only thing checked.** Nothing in `tsc`, ESLint or `next build` can see it, because the comparison is well-formed; only a probe with a forged header does. The two halves of the fix are always paired — remove the header path, and fail **closed** when the secret is missing, because "no secret configured" and "wrong secret" must both deny.
- **an-unset-secret-and-a-wrong-secret-must-both-deny** — A gate written as `expected = process.env.SECRET || ''` and then `provided === expected` authorizes **everyone** when the env var was never configured, because the empty string equals the empty string. The failure mode is silent and total: the route looks gated in code review and is wide open in production. Any secret comparison needs an explicit "is the secret configured?" check that returns an error before the comparison, and a length check so a truncated or empty presented value cannot match.
- **a-gate-that-repairs-the-state-it-inspects-cannot-find-the-defect** — The first version of the deploy-source-of-truth gate refreshed the connected branch with `git fetch origin refs/heads/main` before comparing, which is the obviously correct thing to do and made the gate blind: the fetch restored `origin/main` to its true remote state *before* the reachability test, so the gate reported "the deployed commit is on the branch" in a clone whose branch genuinely did not contain it. The proof attempt failed for exactly that reason and looked like a flaky gate. Read the remote with `git ls-remote` (which touches nothing) and fetch a commit **by SHA** only when it is genuinely missing from the object store. The general form: **a check must not fix, refresh, or repair the thing it is checking**, or the check cannot report a defect it would otherwise have found. It also has a second benefit — `ls-remote` leaves the working tree alone, so the gate is safe to run from a dirty checkout, which is exactly when you most want to run it.
- **a-secret-in-production-can-be-read-through-the-cli-even-when-the-api-wont-return-it** — Vercel's API returns an `encrypted` variable as an opaque ciphertext blob (`{"v","c","k"}`), but `vercel env pull` decrypts it, because the CLI holds the project key. The failure was visible only by looking at the data the route was supposed to produce. The mirror of "exercise the write path, don't read the log": exercise the *read* path against live data and check that the rows are actually there.ent, this repo, now published correctly) and a curated publisher outside this repo writes `<topic>-<date>` with a scheduled `published_at` and no `status`. Two rows can exist for one day; only the site's row is published. Do not "fix" one by publishing the other without the owner deciding which is the intended issue.
- **a-rejection-gated-on-the-secret-being-present-fails-open** — `if (SECRET && provided !== SECRET) return 401` reads like a check but is a **conditional check**: when the secret is unset the whole condition is false and the route proceeds. "The secret was never configured" turns into "everyone is authorized". The fix is two statements, not one: reject when the secret is missing, **then** compare. An unset secret and a wrong secret must both deny — and both must deny *differently*, because "not configured" (503) and "wrong credential" (401) are different operator problems.
- **an-empty-secret-satisfies-an-empty-comparison** — `constantTimeEqual('', '')` returns **true**: the buffers are zero-padded and the length check passes. So a route that compares a caller-supplied bearer against an unset env var authenticates the empty bearer. Any comparison against a secret needs a guard that rejects an empty value *before* the comparison, and the comparison must be against a **value** (a constant-time call, or `===` against an identifier) — comparing against a literal or reporting a boolean is configuration, not authentication, and a gate that flags those is a gate that gets ignored.
- **a-defect-class-is-not-a-repo-property** — The fleet is a set of independent checkouts that share patterns but not code, so a shape copied between sites reappears wherever it lands. Session 54's hand sweep found the shape in one repo; session 55's command swept **63 checkouts** and found it on another client's site *and* in two archived copies of the first one. A gate that runs in one repo is a gate that only runs in one repo — and an archived copy with a live `.vercel` link is a loaded gun, because a `vercel --prod` from the wrong folder ships it to production.
- **a-latent-defect-is-still-a-defect** — Imperium's cron routes were not exploitable *at that moment* (the secret was set, and the 0-env-var deployment sat behind Vercel Authentication). They would have opened the next time the secret went missing. "Not currently reachable" is a property of the environment, not of the code, and the environment changes without anyone editing the route.
- **a-copy-with-a-vercel-link-is-not-an-archive** — `.vercel/project.json` is what `vercel --prod` reads to decide which project it deploys to. A directory holding one is a **deployable tree**, whatever else it looks like — a worktree, a scratch directory, a month-old release snapshot. Treating it as an archive is how a fixed defect stays one command from being live. The durable rule: a copy is safe only if it is clean *or* it cannot deploy, and the fleet sweep has to check the second population separately from the canonical surfaces.
- **patch-the-minimal-shape-not-the-whole-file** — Copying the canonical file into a stale tree to apply one security fix also copies every unrelated difference and destroys whatever other work that tree carried. A targeted exact-match substitution changes only the defect, and — critically — it must require **all** its replacements to match before it writes: a partial rewrite is how a subtle bug gets shipped.
- **a-fixed-source-does-not-fix-the-build-cache** — After the sources were patched, the bypass was still present in the compiled `.next/` output of this repo and of several scratch worktrees. The two are separate artifacts: the source is what Vercel builds, the cache is what a local `next start` serves. Neither reaches production on its own (the cache is git-ignored and never uploaded, and only `.vercel/output` is uploaded by a prebuilt deploy), but a fixed source with a stale cache is a repo that still serves the old behaviour locally — and "it can't reach production" is a claim to *measure* (grep the artifact, check the prebuilt output directories), not to assume.
- **a-failed-credential-is-not-an-empty-result** — A gate that flattens every non-OK API response to `null` cannot tell "the credential expired" from "there is nothing there", and it will confidently print the second. For the deploy gate that means "the Vercel API returned no production deployments" when production is running perfectly and the token had simply expired — the operator is sent to look for a missing deployment instead of a re-login. Two rules follow: a credential failure must **fail closed** with the status and an explicit "the result is UNKNOWN" (never a clean result, never a `null` that reads as an empty list), and a token supplied through the environment must never be **silently replaced** by a local credential — a rejected CI token that quietly borrows the developer's identity is a different bug wearing the same mask. The fix is also mechanical: refresh the credential through the same flow the tool itself uses (the Vercel CLI's own OAuth refresh, writing the new token back so the tool and the scripts agree) instead of reading the auth file once and hoping.
- **a-gate-that-did-not-run-has-established-nothing** — A gate whose rule set is missing must **fail closed**, not warn and pass. `audit-anon-rls.ts` printed "scanned 879 files — 0 findings" and exited 0 whenever `scripts/anon-locked-tables.json` was absent — the three locked-table rules had no tables to check, so the scan found nothing because there was nothing to find. That is the same shape as the expired Vercel credential: **a missing precondition reported as a clean result**. The fix is to check the precondition **first**, exit non-zero with the reason, and never print the "0 findings" line — that line is what a reader (and a CI step) takes as evidence. The population it hid was thirty deployable copies of this repo, each carrying 250–255 real findings.
- **behind-by-N-commits-is-wrong-across-diverged-clones** — One copy of this repo reported itself "2 commits behind" the canonical surface while its history did not contain the fix commit at all. A commit count is only meaningful when both sides share a history, and the fleet's clones do not: they descend from the same origin but their branches diverge. The question that matters is *does this tree descend from the fix?*, which `git merge-base --is-ancestor <fix> HEAD` answers exactly.
- **the-operator-tooling-is-part-of-the-security-posture** — A route is not the only thing that can be wrong in a checkout. The scripts an operator runs to probe production are **operator tooling**, and a stale copy of one is a script that reports the wrong thing: the old `audit-env-drift.ts` calls every production variable unreadable when its own credential has expired, and the old `telegram-webhook-setup.mjs` sends a drifted local `CRON_SECRET` and reads the 401 as "the bot token is revoked". Those scripts do not ship to production, but they are how the operator **decides** what to fix, so a copy of them that lies sends the repair in the wrong direction. Two consequences: a deployable copy must carry the canonical surface's current operator tooling, and the fleet sweep must compare it — a **copy divergence** is not only a route that still holds an auth bypass, it is a script that no longer carries its fix.
- **a-source-map-embeds-the-source-comments-too** — Grepping a build artifact for a defect shape has a third false-positive source besides the substring problem: a `.map` file holds the **original source**, comments included. Next strips comments from the compiled chunk but not from its source map, so a chunk that carries the fix — and the comment *explaining* the fix — matches in the map while the compiled JavaScript is clean. The Imperium pair was exactly this: 0 matches in the compiled JS, 1 in `_09ykazy._.js.map`, and the match was the sentence "This route used to accept the `x-vercel-cron: 1` request header as an alternative". **Read the match before treating it as a defect**, and count the compiled JS and the maps separately — otherwise a rebuild that worked perfectly looks like it did not.
- **a-rule-must-fire-on-the-real-pre-fix-tree-and-go-quiet-after** — A new gate rule is not proven until it has been seen to fire against the actual defect and then go silent once the defect is gone. Both new rules were proven by **reverting** the copy's scripts to the pre-fix versions, running the sweep (it reported the divergences), then removing the module it needs (it reported the missing module), then restoring both (it returned to zero). A rule that has never been seen red is not a rule.
- **grep-the-shape-not-the-substring** — A search for `x-vercel-cron` in the Imperium build cache matched the **legitimate** `x-vercel-cron-token` header — the secret-carrying one the gate explicitly allows — and produced six false positives that looked like live bypasses in two canonical checkouts. The precise pattern is `x-vercel-cron` **not** followed by `-token`; the cron-auth gate itself carries the same refinement (`/x-vercel-cron(?!-)/i`). A grep that finds a substring finds the *word*, not the *defect*, and a false positive in a security sweep is not a harmless thing: it makes the real findings easier to dismiss.
- **a-tree-with-no-vercel-link-is-not-a-tree-with-no-defect** — The fleet sweep had a hole between its two phases: the canonical phase skipped scratch trees ("not deployed surfaces") and the copy phase only looked at trees carrying a `.vercel` link ("deployable surfaces"), so a tree with the defect and **no** link was invisible to both — and that is where **23 of them** were. Deployability is a property of a tree *today*, not a property of its code: `vercel --prod` from an unlinked folder, or a copy into a canonical slot, makes it deployable in one command. So the gate needs a third population — trees that carry the defect and cannot deploy *yet* — reported as findings, because the cost of the false negative is a shipped bypass and the cost of the finding is a patch. The same reasoning applies to any "this directory is inert" assumption: **an inert directory is a deployment waiting for a command, not an archive**.
- **a-path-with-a-space-silently-splits-a-file-list** — `find … | xargs grep` (without `-print0`) splits the file list on whitespace, so every path under a directory whose name contains a space — `Sitani Mafi/Omni AI/` — is passed as two wrong filenames, and `grep` reports *no match* without saying why. This is not theoretical: the first fleet-wide search for the cron bypass missed three trees entirely because of it, and the "0 findings" it printed was an artifact of a broken command rather than a clean fleet. `find … -print0 | xargs -0 grep …` is the only correct form for a fleet that contains spaces, and a fleet sweep must be **re-run** when its command shape changes — the earlier count was not wrong by arithmetic, it was wrong by invocation.

## ⚡ Rules
- Read this file first, every session
- Never repeat anything in Edit History
- Check patterns before writing new code
- Build before and after every change
- Run `npm run audit:mobile` before every ship — it is the only check that sees the mobile defect classes
- Run `node scripts/audit-live-mobile.mjs --all` before every ship — the only check that sees HTTP status, soft-404s, console errors, and broken images
- Run `npm run audit:flash` before every ship — the only check that sees what the canvas was doing while the stylesheet was still downloading; a settled-page check cannot see a first-paint flash
- Run `npm run audit:publish` before every ship — the only check that sees a half-published newsletter row **and a reader that advertises drafts that 404** (2 rules)
- Never decide "this newsletter row is public" from `published_at` alone — use `publishedNewsletterOnly()` from `lib/newsletter-posts.ts`; the two markers can disagree and 325 rows in the live table DO
- Run `npm run audit:env-drift` before debugging any auth/secret failure — a 401 can be a wrong local credential, not a revoked token
- After changing a `<head>`/metadata field, grep the SERVED page for the resulting tag — `metadata.themeColor` type-checks, builds, and emits nothing; the tag comes from the `viewport` export
- Run `npm run audit:rls` before every ship — the only check that sees a read that returns `[]` because RLS said no
- Run `npm run audit:cron-auth` before every ship — the only check that sees a route authenticating with a header the caller chooses, or a secret comparison that an unset env var would satisfy
- Run `npm run audit:fleet-auth` before a cross-project release — the defect class travels by copy, and an archived checkout with a live `.vercel` link will ship it if anyone deploys from it
- A tree with **no** `.vercel` link is not a tree with no defect — `npm run audit:fleet-auth` now sweeps unlinked trees too, because a scratch tree is one `vercel --prod` away from shipping
- Sweep the fleet with `find … -print0 | xargs -0 …` — a path containing a space splits the file list and hides findings without saying why
- A gate that did not run has established nothing — check the precondition first and exit non-zero; never print a "0 findings" line for a rule set that never loaded
- Never report a commit count across diverged clones — use `git merge-base --is-ancestor` to ask whether a tree descends from a fix
- A source map embeds the source's comments — count a build artifact's compiled JS and its `.map` files separately, and read the match before calling it a defect
- The operator tooling is part of the security posture — a deployable copy must carry the canonical surface's current operator scripts, and `npm run audit:fleet-auth` must say so
- A failed credential is not an empty result — an API gate must print the status and say the result is UNKNOWN, and must never substitute a local credential for one supplied in the environment
- A directory with a `.vercel` link is a deployable tree, not an archive — sweep it, and patch the minimal shape rather than copying canonical files into it
- Reject when the secret is **unset**, then compare — one statement (`if (SECRET && …)`) is a conditional check, and the condition is false exactly when the secret is missing
- An empty bearer must not satisfy a comparison against an unset secret — `constantTimeEqual('', '')` is `true`
- Never read or write an `omni_*` table with the anon key — RLS answers 200 with an empty array and the write no-ops. Server route + `createAdminClient()` + the gate in `lib/server/dashboard-access.ts`
- A service-role route is a privileged route: give it a tenancy check in the same commit that gives it the service role
- Never reintroduce a root `app/loading.tsx` — it silently breaks every 404 on the site
- Do not fix a white flash by adding a `loading.tsx` — the critical background is an inline `<style>` in the root layout's `<head>`, and a loading boundary above a 404-capable route trades a cosmetic flash for a soft 404
- When measuring a background, read `document.documentElement` — the canvas is painted with the `html` background whenever the `body` is transparent, so a body-only probe always reads `rgba(0, 0, 0, 0)`

- A new route that can 404 must have no `loading.tsx` above it, and must be added to the live audit's coverage
- Never touch .env files
- Commit every logical unit: `agent: [what]`
- Push when done
- Ship through the federation protocol: resolve the surface, acquire the lease, push `main`, poll the deployment for the pushed SHA, verify the live HTML, release the lease with the deploy journal
