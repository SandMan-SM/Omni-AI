## 🌐 Patterns To Apply
- **audit-the-defects-the-toolchain-cannot-see** — A defect class that survives `tsc` and `next build` will come back every time, because nothing in the pipeline looks for it. Fix the class, then encode it as a one-second check that exits non-zero: `npx tsx scripts/audit-send-domains.ts` for the Resend allowlists, `npm run audit:mobile` for the mobile defect classes. The gate is worth more than the fix — session 43 fixed the visible instances by hand and session 44's gate immediately found 63 more across 40 files.
- **tailwind-merge-height-precedence** — `components/ui/input.tsx` sets a fixed `h-9`, so a call site passing `py-5` does NOT grow the field: tailwind-merge keeps both (different property groups) and the fixed height wins, rendering a 36px box with 20px of padding crammed inside it. To change the height, pass `h-12`/`h-auto` — never `py-*` alone. The same applies to every shared component with a fixed height.
- **ios-16px-input-floor** — iOS Safari zooms the viewport when a focused field's computed font-size is under 16px, which breaks the 375px layout mid-typing. The `Input` component already gets this right (`text-base … md:text-sm`); bare `<input>`/`<textarea>` elements with `text-sm`/`text-xs` or an inline `fontSize: 13` do not. Audit raw form controls, not just the shared component — there were 20+ offenders, and the dashboard's inline `style={{ fontSize: 13 }}` ones cannot be rescued by a Tailwind responsive class.
- **mobile-44px-without-losing-desktop-density** — Set touch targets with the mobile value first and a `md:` override for the desktop value (`min-h-11 md:min-h-9`, `h-11 md:h-9`). Bumping the base size alone changes desktop density everywhere; the `md:` override keeps the desktop layout identical while giving mobile the 44px minimum.
- **overlay-needs-three-things** — Every `fixed inset-0` overlay needs `h-[100dvh]` on the backdrop (not `inset-0` alone), a `max-h-[90dvh]` cap on the panel, and a scroll container inside it. The auth-modal pattern is the reference: shell owns `max-h-[90dvh] flex flex-col overflow-hidden`, inner `<div>` owns `overflow-y-auto p-8 flex-1`, and the close button stays `absolute` outside the scroller. Without all three, the submit button is clipped out of reach on a short viewport.
- **grid-1fr-needs-minmax-0** — Tailwind's `grid-cols-[1fr_auto_1fr]` uses `minmax(auto, 1fr)`, so a track's automatic minimum is its cell's min-content. Long prose in a card will therefore push the grid wider than its container rather than wrap. Use `grid-cols-[minmax(0,1fr)_auto_minmax(0,1fr)]` when the tracks hold text, and stack to one column below `sm` when they hold sentences.

- **seo-metadata-factory** — Route metadata goes through `buildMetadata()` in `lib/seo.ts` instead of a hand-rolled object. Client pages can't export `metadata`, so they get a sibling `layout.tsx` that exports it and renders `children`.
- **twitter-handle-parity** — Any page that overrides the `twitter` block must re-declare `site`/`creator: "@SitaniMafi"`. Next.js metadata is shallow-merged, so a partial override silently drops the root's fields.
- **brand-truth-from-db** — When a tenant's brand is in question, the live `omni_businesses` row is the authority, not the code. `select name, website, industry from omni_businesses where slug = '<tenant>'` gave "Clinical and Professional Solutions" / cpsutah.org / "Utah community and professional solutions" while fourteen files still said "Psych & Custody Evaluations". Read the row first, then sweep the code to match it — and cross-check `case-studies.ts` (federation vocabulary) against `omni_businesses.slug` (DB vocabulary), which are deliberately different.
- **resend-allowlist-is-live-data** — Any list of "domains we can send from" is a cache of the Resend account and rots silently. Reconciled 2026-10-22: the account holds exactly ten verified domains, and the old lists still named three domains that are not in it. Or just run `npx tsx scripts/audit-send-domains.ts`: it diffs both allowlists against the live account, lists `active` campaigns that would 403 at send time, and exits non-zero on drift so it works as a pre-blast gate.

- **federation-over-postgrest** — `federation.surfaces` / `work_leases` / `changelog` are NOT exposed as PostgREST tables and direct Postgres is DNS-blocked from the agent's machine. Reach them through the RPCs instead: `POST /rest/v1/rpc/hermes_federation_surface` with `p_domain`, `hermes_federation_acquire_lease` with `p_target/p_agent/p_kind/p_session_ref/p_note/p_ttl_minutes`, and `hermes_federation_release_lease` with `p_lease_id/p_agent/p_action/p_detail`. Listing the RPC names: `GET /rest/v1/` with `Accept: application/openapi+json`. `hermes_federation_surface` returns the surface row AND the last few changelog rows in one call — read the changelog before touching the surface, it tells you what the last agent did and which commit prod is pinned to.
- **verify-live-after-vercel-cli-deploy** — `npx vercel --prod` prints `Aliased: https://omnileadsagi.com` at the end, but the alias only flips once the deployment is READY. Verify the fix by grepping the live HTML for the exact class or attribute you changed (e.g. `curl -s https://omnileadsagi.com/cps/marketing | grep -c 'minmax(0,1fr)'`) rather than trusting the CLI's exit code. Remember `tailwind-merge` may drop the base class you edited when a call site overrides it — a grep miss on the base class is not a failed deploy.
- **ast-not-regex-for-accessible-name** — Whether a JSX expression renders text is not decidable from the source text, so an accessible-name rule must walk the TypeScript AST (`ts.createSourceFile` + `ts.forEachChild`), not the file's characters. `{active ? <Pause/> : <Play/>}` renders no name while `{u.name || u.email}` renders one, and the regex sees the same thing in both. The first regex attempt produced ~45 false positives; the AST version had to grow a case for every expression shape (`??`, property access, numeric literal, `+` concatenation, conditional, call expression) as each false-positive batch surfaced. Corollary: the AST walker cannot see across a component boundary, so a control nested inside a capitalised (custom) component must be skipped rather than reported.
- **route-handler-beats-page-redirect** — A page-level `redirect()` in the App Router is **prerendered at build time and served as a 200 with a `<meta http-equiv="refresh">` tag**, even with `export const dynamic = "force-dynamic"` in the route file (verified live: the served page carried the meta tag and answered 200). If the redirect must be a real HTTP redirect for crawlers, use a **route handler** — `NextResponse.redirect(url, 308)` — and delete the page, because a page and a route handler cannot share a segment. Export `HEAD` alongside `GET` so a link checker probing with HEAD is not handed a 405.
- **a-root-dynamic-route-swallows-dead-links** — `app/[slug]/page.tsx` (the DB-backed daily landing page) matches **any single-segment path**, so a route-existence check built from the route table treats `/auth`, `/login`, and `/does-not-exist` alike as valid. Any dead-link rule must therefore restrict itself to paths with **two or more segments**, or the rule reports zero findings forever while the real break is live. The `/auth` soft-404 survived three sessions of link auditing for exactly this reason.
- **a-gate-must-say-how-many-rules-it-ran** — An audit that prints "0 findings across 0 rules" (rules-that-fired) reads like a gate that ran nothing, and a rule that fires under a typo'd name is counted under a name no reader recognises. Keep an explicit `RULE_NAMES` registry, report its length in the summary, and exit non-zero when a finding's rule name is not in it. Prove the gate is alive by seeding deliberate defects into a scratch file and confirming it fires and exits 1.
