## 🌐 Patterns To Apply
- **audit-the-defects-the-toolchain-cannot-see** — A defect class that survives `tsc` and `next build` will come back every time, because nothing in the pipeline looks for it. Fix the class, then encode it as a one-second check that exits non-zero: `npx tsx scripts/audit-send-domains.ts` for the Resend allowlists, `npm run audit:mobile` for the mobile defect classes. The gate is worth more than the fix — session 43 fixed the visible instances by hand and session 44's gate immediately found 63 more across 40 files.
- **tailwind-merge-height-precedence** — `components/ui/input.tsx` sets a fixed `h-9`, so a call site passing `py-5` does NOT grow the field: tailwind-merge keeps both (different property groups) and the fixed height wins, rendering a 36px box with 20px of padding crammed inside it. To change the height, pass `h-12`/`h-auto` — never `py-*` alone. The same applies to every shared component with a fixed height.
- **ios-16px-input-floor** — iOS Safari zooms the viewport when a focused field's computed font-size is under 16px, which breaks the 375px layout mid-typing. The `Input` component already gets this right (`text-base … md:text-sm`); bare `<input>`/`<textarea>` elements with `text-sm`/`text-xs` or an inline `fontSize: 13` do not. Audit raw form controls, not just the shared component — there were 20+ offenders, and the dashboard's inline `style={{ fontSize: 13 }}` ones cannot be rescued by a Tailwind responsive class.
- **mobile-44px-without-losing-desktop-density** — Set touch targets with the mobile value first and a `md:` override for the desktop value (`min-h-11 md:min-h-9`, `h-11 md:h-9`). Bumping the base size alone changes desktop density everywhere; the `md:` override keeps the desktop layout identical while giving mobile the 44px minimum.
- **overlay-needs-three-things** — Every `fixed inset-0` overlay needs `h-[100dvh]` on the backdrop (not `inset-0` alone), a `max-h-[90dvh]` cap on the panel, and a scroll container inside it. The auth-modal pattern is the reference: shell owns `max-h-[90dvh] flex flex-col overflow-hidden`, inner `<div>` owns `overflow-y-auto p-8 flex-1`, and the close button stays `absolute` outside the scroller. Without all three, the submit button is clipped out of reach on a short viewport.
- **grid-1fr-needs-minmax-0** — Tailwind's `grid-cols-[1fr_auto_1fr]` uses `minmax(auto, 1fr)`, so a track's automatic minimum is its cell's min-content. Long prose in a card will therefore push the grid wider than its container rather than wrap. Use `grid-cols-[minmax(0,1fr)_auto_minmax(0,1fr)]` when the tracks hold text, and stack to one column below `sm` when they hold sentences.
- **seo-metadata-nextjs** — Standard Next.js metadata export with title, description, openGraph, a
- **seo-metadata-factory** — Route metadata goes through `buildMetadata()` in `lib/seo.ts` instead of a hand-rolled object. Client pages can't export `metadata`, so they get a sibling `layout.tsx` that exports it and renders `children`.
- **twitter-handle-parity** — Any page that overrides the `twitter` block must re-declare `site`/`creator: "@SitaniMafi"`. Next.js metadata is shallow-merged, so a partial override silently drops the root's fields.
- **brand-truth-from-db** — When a tenant's brand is in question, the live `omni_businesses` row is the authority, not the code. `select name, website, industry from omni_businesses where slug = '<tenant>'` gave "Clinical and Professional Solutions" / cpsutah.org / "Utah community and professional solutions" while fourteen files still said "Psych & Custody Evaluations". Read the row first, then sweep the code to match it — and cross-check `case-studies.ts` (federation vocabulary) against `omni_businesses.slug` (DB vocabulary), which are deliberately different.
- **resend-allowlist-is-live-data** — Any list of "domains we can send from" is a cache of the Resend account and rots silently. Reconciled 2026-10-22: the account holds exactly ten verified domains, and the old lists still named three domains that are not in it. Or just run `npx tsx scripts/audit-send-domains.ts`: it diffs both allowlists against the live account, lists `active` campaigns that would 403 at send time, and exits non-zero on drift so it works as a pre-blast gate.
- **deploy-verify-poll** — After `git push origin main`, Vercel's git auto-deploy can take 15–20+ minutes to even appear. Empty GitHub `check-runs` proves nothing. Poll the Vercel API (`/v6/deployments?projectId=...`) for ~20 min, matching `meta.githubCommitSha` to the pushed SHA. If prod must be live sooner, run `python3 scripts/omniclaw_deploy_guard.py deploy Website --mode prod` from `/Users/janahasson/Desktop/Clients/Sitani Mafi/Omni AI` (stop any dev server in that checkout first — the guard runs a real `next build`).
- **federation-over-postgrest** — `federation.surfaces` / `work_leases` / `changelog` are NOT exposed as PostgREST tables and direct Postgres is DNS-blocked from the agent's machine. Reach them through the RPCs instead: `POST /rest/v1/rpc/hermes_federation_surface` with `p_domain`, `hermes_federation_acquire_lease` with `p_target/p_agent/p_kind/p_session_ref/p_note/p_ttl_minutes`, and `hermes_federation_release_lease` with `p_lease_id/p_agent/p_action/p_detail`. Listing the RPC names: `GET /rest/v1/` with `Accept: application/openapi+json`. `hermes_federation_surface` returns the surface row AND the last few changelog rows in one call — read the changelog before touching the surface, it tells you what the last agent did and which commit prod is pinned to.
- **verify-live-after-vercel-cli-deploy** — `npx vercel --prod` prints `Aliased: https://omnileadsagi.com` at the end, but the alias only flips once the deployment is READY. Verify the fix by grepping the live HTML for the exact class or attribute you changed (e.g. `curl -s https://omnileadsagi.com/cps/marketing | grep -c 'minmax(0,1fr)'`) rather than trusting the CLI's exit code. Remember `tailwind-merge` may drop the base class you edited when a call site overrides it — a grep miss on the base class is not a failed deploy.
- **ast-not-regex-for-accessible-name** — Whether a JSX expression renders text is not decidable from the source text, so an accessible-name rule must walk the TypeScript AST (`ts.createSourceFile` + `ts.forEachChild`), not the file's characters. `{active ? <Pause/> : <Play/>}` renders no name while `{u.name || u.email}` renders one, and the regex sees the same thing in both. The first regex attempt produced ~45 false positives; the AST version had to grow a case for every expression shape (`??`, property access, numeric literal, `+` concatenation, conditional, call expression) as each false-positive batch surfaced. Corollary: the AST walker cannot see across a component boundary, so a control nested inside a capitalised (custom) component must be skipped rather than reported.
- **route-handler-beats-page-redirect** — A page-level `redirect()` in the App Router is **prerendered at build time and served as a 200 with a `<meta http-equiv="refresh">` tag**, even with `export const dynamic = "force-dynamic"` in the route file (verified live: the served page carried the meta tag and answered 200). If the redirect must be a real HTTP redirect for crawlers, use a **route handler** — `NextResponse.redirect(url, 308)` — and delete the page, because a page and a route handler cannot share a segment. Export `HEAD` alongside `GET` so a link checker probing with HEAD is not handed a 405.
- **a-root-dynamic-route-swallows-dead-links** — `app/[slug]/page.tsx` (the DB-backed daily landing page) matches **any single-segment path**, so a route-existence check built from the route table treats `/auth`, `/login`, and `/does-not-exist` alike as valid. Any dead-link rule must therefore restrict itself to paths with **two or more segments**, or the rule reports zero findings forever while the real break is live. The `/auth` soft-404 survived three sessions of link auditing for exactly this reason.
- **a-gate-must-say-how-many-rules-it-ran** — An audit that prints "0 findings across 0 rules" (rules-that-fired) reads like a gate that ran nothing, and a rule that fires under a typo'd name is counted under a name no reader recognises. Keep an explicit `RULE_NAMES` registry, report its length in the summary, and exit non-zero when a finding's rule name is not in it. Prove the gate is alive by seeding deliberate defects into a scratch file and confirming it fires and exits 1.
- **a-loading-boundary-commits-the-http-status** — A `loading.tsx` anywhere in a route's segment chain creates a Suspense boundary **above** the page component; Next flushes that fallback first and **the HTTP status is committed with the first flush**, so a later `notFound()` throw can no longer set it — the 404 ships as **200**. A segment's `loading.tsx` applies to that segment **and its children**, so one root `app/loading.tsx` breaks the 404 behaviour of every route in the app. Route segment config on `not-found.tsx` changes nothing. Fix: no `loading.tsx` above a 404-capable route; put the skeleton in an internal `<Suspense>` inside the page, and make sure that page never 404s.
- **verify-a-404-with-a-browser-not-with-curl** — A 404 served without a loading boundary returns `<html id="__next_error__">` with an **empty `<body></body>`** server-side and a `NEXT_NOT_FOUND` digest; the branded UI hydrates in the browser. `curl` + grep for the UI text therefore reports a false negative ("the page is broken"). Check the status with a real browser — the live audit gate reads `performance.getEntriesByType('navigation')[0].responseStatus`.
- **audit-flags-must-accept-the-equals-form** — Parse `--name value` **and** `--name=value`. The `=` form is what people actually type, and silently falling back to the default host on a typo'd flag means you audit PRODUCTION by accident when you meant localhost. The same applies to any host/URL filter inside the tool: a sitemap advertises the canonical production host, so filter on `new URL(u).pathname`, never on the base host.
- **a-sitemap-must-only-list-urls-that-resolve** — 332 of the sitemap's 468 URLs pointed at newsletter rows that were never published on this site. Every unresolvable URL in the sitemap is a crawl-budget leak and a signal to a crawler that the site manufactures URLs. Filter the query to what actually renders (`status = published`, non-null slug and `published_at`, and an explicit tenant filter) rather than trusting the table.
- **a-sitemap-cannot-prove-a-404** — The sitemap proves that real URLs resolve. It can never prove that a bogus one does not. The sitemap's absence of a URL is not evidence that the route 404s. The only proof is a **probe**: a path that cannot exist, asserted to answer HTTP 404. The live audit keeps `NOT_FOUND_PROBES` (one bogus slug per dynamic route family) and fails when any of them answers anything else. Add a probe the moment a route starts calling `notFound()`.
- **eslint-disable-for-satori-only** — `.eslintrc.json` overrides `@next/next/no-img-element` for opengraph/twitter image files, because satori requires a raw `<img>`. Without the override the build emits a warning on every image route.
- **a-publish-must-set-status-and-published_at-together** — A row with `published_at` set but `status` left at its `'draft'` default is a **half-published row**: it looks published in the database and in every log, but every reader filters on `status = 'published' AND published_at IS NOT NULL` and therefore never shows it. The `newsletter_posts` table lost 80 days of daily issues this way — the cron logged `published: true` every day while the issue existed nowhere. Whenever a writer sets a publish timestamp, set the status column in the SAME statement, and treat "timestamp set but status not" as a state that should be impossible. A `status` column with a `'draft'` default will silently swallow the omission.
- **a-log-that-claims-success-is-not-evidence** — The newsletter cron wrote `newsletter_public_published` with `published: true` for 80 consecutive days while publishing nothing. Event logs record intent, not outcome. When auditing a pipeline, compare the log against the **state it claims to have changed** (is the row in the sitemap? does the page return 200?) — a green log plus an unchanged table is the signature of a silent write failure.
- **a-column-default-of-now-is-a-publish-trap** — `newsletter_posts.published_at` is `timestamptz DEFAULT now()` and `status` is `text DEFAULT 'draft'`. A writer that omits `published_at` gets the current time stamped on a draft, and a writer that omits `status` gets a draft that looks timestamped — the two omissions look identical in the code review but mean opposite things in the database. Read the column defaults out of the live schema (`GET /rest/v1/` with `Accept: application/openapi+json` lists every default) before trusting any write path, and set both columns explicitly in the same statement. The right schema default for `published_at` is NULL; changing it is a migration.
- **exercise-the-write-path-dont-read-the-log** — The only proof that a publish works is to publish and look at the result: call the real endpoint with the production `CRON_SECRET` (`GET /api/cron/newsletter?action=publish-public` has no email side effects), then check the row's `status`/`published_at`, the issue page's HTTP status, the archive, and the RSS feed. Reading the cron log proves only that the cron ran.
- **a-cli-deploy-is-not-a-source-of-truth** — A Vercel CLI deploy from an isolated worktree produces a **production deployment with no `meta.githubCommitSha`**. That is the tell: git is the source of truth, the CLI is only the transport, and if the deployed bytes were never committed, the next git-triggered build is a silent rollback of whatever the CLI put live. After any such deploy, diff the deployed tree against git for **every tracked file** (`git ls-files -z | xargs -0 shasum -a 256` on both sides) and commit the delta before the next push. Also check for files that were uploaded but are git-ignored: the AIS release had seven, and three of them were **served live and answered 200**, so a git build would have traded a working URL set for a 404 set. Track what is served; leave the rest ignored. Runbook: `runbook.deploy/git-is-the-source-of-truth-after-a-cli-deploy`
- **check-the-deployed-commit-is-reachable-from-the-connected-branch** — `source: 'cli'` on a deployment is not by itself a defect; most of this portfolio ships that way and the deployment still carries a commit that is in the connected repo. The defect is narrower and sharper: a git-connected project whose **deployed commit is absent from the connected branch**. Sweep it with `link.repo` from `GET /v9/projects/{id}` plus `meta.githubCommitSha` / `meta.gitCommitSha` from `GET /v6/deployments?projectId=…&target=production&limit=1`, then test reachability against the branch. Runbook: `runbook.deploy/cli-deploys-vs-git-connected-projects`
- **the-sitemap-data-cache-lags-a-newly-published-issue-by-an-hour** — `app/sitemap.ts` exports both `revalidate = 3600` and `dynamic = "force-dynamic"`. The page's `lastmod` is computed per request, so the sitemap *looks* fresh on every fetch while its URL set comes from Next's data cache and can lag an hour behind a publish. A newly published issue enters the sitemap within the hour — acceptable for a daily cadence, but do not read "the sitemap is missing my new post" as "the publish failed".
- **a-newsletter-day-has-two-writers** — The site cron writes `interlinked-<tier>-<date>` (AI-generated content, this repo, now published correctly) and a curated publisher outside this repo writes `<topic>-<date>` with a scheduled `published_at` and no `status`. Two rows can exist for one day; only the site's row is published. Do not "fix" one by publishing the other without the owner deciding which is the intended issue.

## ⚡ Rules
- Read this file first, every session
- Never repeat anything in Edit History
- Check patterns before writing new code
- Build before and after every change
- Run `npm run audit:mobile` before every ship — it is the only check that sees the mobile defect classes
- Run `node scripts/audit-live-mobile.mjs --all` before every ship — the only check that sees HTTP status, soft-404s, console errors, and broken images
- Run `npm run audit:publish` before every ship — the only check that sees a half-published newsletter row
- Never reintroduce a root `app/loading.tsx` — it silently breaks every 404 on the site
- A new route that can 404 must have no `loading.tsx` above it, and must be added to the live audit's coverage
- Never touch .env files
- Commit every logical unit: `agent: [what]`
- Push when done
- Ship through the federation protocol: resolve the surface, acquire the lease, push `main`, poll the deployment for the pushed SHA, verify the live HTML, release the lease with the deploy journal
