# Portfolio newsletter catalog and editorial tags

AIS Empire reads the portfolio newsletter catalog from `GET /api/reporting/ais-empire/newsletter`. Both the service credential and a Supabase-verified session are required. Authorization checks the immutable platform owner `9de99ed9-e7ec-4a85-824e-c812944dff9c`; a general platform role or brand membership is insufficient. The response is private, noncacheable, and excluded from indexing. This endpoint cannot publish, enroll subscribers, or send messages.

Supported query fields are `source`, `niche`, `tag`, `status`, `search`, `sort`, `page`, and `page_size`. Sorts are `newest`, `oldest`, `title`, and `source`. The default page size is 25 and maximum is 100. The catalog reads one consistent PostgreSQL snapshot without a Data API row limit. Filtering and pagination run after normalization and source deduplication; the response carries full-catalog options and a separate filtered pagination total. Niches and their tags sort alphabetically. Tags are generated from actual stored classifications or native tags, never guessed from article titles.

The source catalog covers registry-resolved portfolio tenants. Public adapters include `newsletter_posts` for Omni AI, `leadfranchise_newsletter_issues`, `newsroom_posts` for the Utah publications, and verified file-backed archives. Legacy federation, Success Empire, and other stored newsletter records are visible to the owner, with no invented public link when the current site has no corresponding reader. A file-backed article supersedes a matching legacy record; a live newsroom database record supersedes its matching Markdown mirror. No issue bodies, subscriber data, delivery credentials, or private dispatch details are included.

Confirmed sites without an archive and without stored issues are omitted from the newsletter dropdown. A known restricted archive and stored issues without public readers receive neutral coverage notes. A failed expected adapter is explicitly unavailable. Database failures, absent classification migrations, unrecognized source identities, malformed records, and snapshot count mismatches fail the entire read rather than returning fabricated empty data.

`public.portfolio_newsletter_classifications` is the durable editorial overlay. Its primary key is `(source_id, post_key)`. Source IDs are registry tenant slugs. Keys namespace native identifiers, such as `newsletter:<uuid>`, `newsroom:<uuid>`, or `static:<slug>`. A classification stores a niche slug and tag labels; for example `niche='general-news'`, `tags=ARRAY['General News']`. Classification updates should explicitly stamp `updated_at`. The table has RLS enabled, no browser policy, revoked anonymous/authenticated grants, and server-only access. Classification changes do not publish content.

Omni public General News issues use `day_type='general-news'` and the web-only `tier='general-news'`. The existing daily generator selects free/premium drafts, so this separate tier prevents it from consuming or sending an editorial web draft. The legacy `/api/newsletter/posts` projection and its fallback likewise include only free/premium content for existing Interlinked automation; General News remains in the public page, archive, RSS, and owner catalog. Use the factual lede in `intro`, authored `{heading, body}` entries in `insights`, and real category/topic labels in `keywords`. Leave optional quote and power-move fields empty when they are not part of the article. Source citations use `[label](https://source.example/page)`; the renderer creates safe React anchors for HTTPS links, rejects embedded credentials, and leaves all HTML literal. These issues receive a General News section, factual share description, editorial byline, and conceptual-art caption. Their generated image lives at `public/newsletter/generated/<slug>.jpg`. The published free front shelf includes the web-only General News tier alongside Interlinked issues while preserving the shared publication-state filter.

Refresh the file-backed metadata snapshot after a site publication. First read `federation.surfaces` and export its current primary rows to an operator-owned JSON file; the registry is the only authority for domain and codebase routing. Then run:

```sh
node scripts/refresh-newsletter-source-catalog.cjs --registry=/absolute/path/to/registry-export.json --database-slugs=/absolute/path/to/newsroom-slugs.json
```

Carry confirmed public availability problems with `--coverage-issues=/absolute/path/to/issues.json`. This optional JSON object maps a source ID to its verified, readable issue. For example, a deployed archive with a DNS failure remains in the catalog and tag results, but receives an explicit coverage issue and no public article links. Retain active issue entries until a real public connectivity check confirms recovery; a successful deployment alone does not clear them.

The optional database-slug JSON maps each newsroom masthead to its canonical database slugs. The SQL reader also deduplicates matching metadata, so omitting this optimization does not cap or duplicate the response. The extractor reads canonical local sources in a restricted VM and writes metadata only to `lib/newsletter-source-catalog.generated.json`. It has no network or credential access. Never publish this snapshot from unrelated dirty code, infer a deployment folder, or embed secrets or workstation paths in the generated JSON.

Verification includes the reporting/calendar tests, `tests/newsletter-source-links.test.ts`, `tests/newsletter-publication.test.ts`, and `tests/general-news-isolation.test.cjs`, plus TypeScript, all repository production-build audits, and an owner-session browser check through the AIS proxy. The isolation tests run the actual free and premium orchestrators, public feed, and Telegram selector against controlled data; they prohibit network and provider calls and verify that neither a draft nor published General News issue enters those selections. `scripts/check-newsletter-report.ts` provides a read-only live database check using environment supplied in memory; it prints counts and coverage only. The host extractor and operator checker are excluded from deployment bundles.

Deploy the central public-feed isolation before publishing a General News database row, preserve its web-only tier, and deploy the authenticated reporting receiver before the AIS caller. Refresh the metadata snapshot after native site releases so catalog links describe deployed pages. The mandatory production-form gate and federation leases continue to apply to every publication, migration, and deployment.
